Pipeline Visualization: Three Approaches

How should we render the core pipeline view that appears in every section?

A

Horizontal Flow (Left-to-Right)

Pipeline stages flow left-to-right like a shell command. Each node shows: operation name, parameters, and a thumbnail preview of the image at that stage. JSON state shown on hover/click. Pipe symbols (|) connect the nodes.

load
cat.jpg
|
resize
50%
|
grayscale
|
save
out.png

Pros

  • Mirrors shell command syntax visually
  • Natural reading direction
  • Pipe symbol reinforces the metaphor

Cons

  • Horizontal scroll on mobile / long pipelines
  • Multi-image (--as/--on) harder to show
B

Vertical Flow (Top-to-Bottom)

Each pipeline stage is a full-width row. Left side shows the operation + params, right side shows the resulting image. For multi-image ops, rows can branch and merge. JSON state expandable per-row.

load
cat.jpg
▼
resize 50%
▼
grayscale
▼
save
out.png

Pros

  • No horizontal overflow
  • Room for branching (multi-image)
  • Each row has space for JSON detail

Cons

  • Doesn't mirror shell syntax as directly
  • Long pipelines push content far down
C

Split View: Command + Diagram

Two-panel layout. Left panel shows the shell command (editable). Right panel shows a horizontal or vertical flow diagram that updates live as the command changes. The command IS the interface; the diagram IS the feedback.

Command
chop load cat.jpg
  | chop resize 50%
  | chop grayscale
  | chop save out.png
Pipeline
load
▼
resize
▼
grayscale
▼
save

Pros

  • Command and visualization side-by-side
  • Editable command = real interactivity
  • Shows the duality: text IS the program, diagram IS the execution

Cons

  • Needs more horizontal space
  • Most complex to implement
